Second run of the doc-reconciliation pass. Verified against main at `8eced56`.

## Method

Pass 1: three read-only agents (normative incrementals; the design tree plus
vectors READMEs; the descriptive tree) extracted and verified claims against code
and vectors, weighting status lines and temporal phrasing highest. Pass 2: one
agent walked the window PRs, one walked the #1-#183 backfill, both from squash
commit bodies. Repairs follow the direction rule: descriptive drift fixed in
scoped `dream/2026-08-11-*` PRs, normative drift appended to the standing per-doc
issues (#294 to #298) or filed as new ones (#341 to #344), decision capture
written into owning docs with provenance, one code-side test-gap issue (#345).

An unusual amount of pass-1 ground was pre-verified: an architecture review
earlier the same day had already swept the session service, engine, API, and
client stores against DESIGN.md and PROTOCOL.md with file:line evidence; this
dream re-grounded those findings and routed them.

## Headline

The behavioral contracts held again: the share surface verified clean against
SHARE.md in every testable claim (token, soft-404, params, caching, INV-6
letter-free posture, replay CSS, budgets), and the check-vote engine matches the
vectors on all three ports. The drift concentrates in exactly the place dream #1
predicted: temporal framing that nobody revisited after the work landed. The two
worst offenders are the twin "execution-skipped until Wave 15.2" claims
(PROTOCOL.md §13 and vectors/README.md), which tell a reader the largest new
vector family does not run when all three runners execute it, and a systematic
two-client blind spot: PROTOCOL.md's consumer line, DESIGN.md's testing table,
ANALYTICS.md's port standard, ROOM-COLORS.md's bucketing list, and four post-game
docs all still describe a world without Android.

One drift item is a genuine owner decision in waiting rather than stale prose:
the shipped check-vote card dismissal policy (dismissible for everyone but an
elector with an uncast ballot, no residual vote indicator after dismissal)
contradicts UX.md's "blocking card / a pending vote is never invisible", and the
code marks itself "flagged for the owner" (#341).
